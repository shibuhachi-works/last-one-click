# 次の版(まだストアに出していない)

ストアに出ている版(v0.1.6)のあとに main にマージした、利用者に関係する変更をためておく所です。ここにある機能は、次の版(v0.1.7)がストアで公開されるまで、ストアから入れた拡張では使えません。

- 拡張の動きを変える PR は、同じ PR でここに 1 行足す(見張り役(`tools/`)・テストだけの変更は書かない)
- リリースの PR で、このファイルを `docs/releases/v0.1.7.md` にし、空の `next.md` を作り直す(手順は [docs/store-submission.md](../store-submission.md))

## 変わったこと

- md の front matter に `note_account`(記事を作る note のアカウントの ID)を書けるようにしました。書くと、編集画面で入力を始める前にログイン中のアカウントと比べ、違えばタイトルも本文も入れずにバナーで知らせて止まります。ポップアップにも「記事の指定」を出し、ログイン中のアカウントと違えば注意を出します。読めないときは止めずに進み、バナーで知らせます。書かなければ今までどおりです
- 診断のレポートの節「ログイン中のアカウントの手がかり」で、埋め込まれたデータのキーを、同じ道筋を 1 つにまとめてから数えるようにしました。同じ形の記事一覧が先にあっても、アカウントの道筋が欠けません
- ポップアップの「note の下書きを作成」の上と、編集画面の右下のバナーに、ログイン中の note アカウントのアイコンと名前を出すようにしました。アカウントを 2 つ持っているときに、違うアカウントで投稿しないためです。note のタブの中から、ログイン中のユーザーの情報を返す note の問い合わせに 1 回だけ問い合わせます(Cookie は読みません。名前とアイコンは画面に出すだけで、保存も送信もしません)。診断のレポートの「ログイン中のアカウントの手がかり」にも、この問い合わせの結果(応答の有無・状態・道筋と文字数だけ)を足しました
- 追加の対応先(library.libecity.com)を使えるようにする仕組みを足しました。そのサイトの新規記事エディタを開いてツールバーのアイコンを押したときだけ、ポップアップに案内が出て、「使えるようにする」を押すとそのサイトへの許可を求めます。入れるときの権限の警告は増えません。切るときは「記事の設定」のスイッチを外します(下書きの入力は、まだ入っていません)
- 本文の Markdown を変換する部品(marked)を 18.2 に新しくしました。太字・斜体の閉じ方や、入れ子の箇条書きの中の見出し・コードの後の文が、より正しく変換されます
