# 次の版(まだストアに出していない)

ストアに出ている版(v0.1.8)のあとに main にマージした、利用者に関係する変更をためておく所です。ここにある機能は、次の版(v0.2.0)がストアで公開されるまで、ストアから入れた拡張では使えません。

- 拡張の動きを変える PR は、同じ PR でここに 1 行足す(見張り役(`tools/`)・テストだけの変更は書かない)
- リリースの PR で、このファイルを `docs/releases/v0.2.0.md` にし、空の `next.md` を作り直す(手順は [docs/store-submission.md](../store-submission.md))

## 変わったこと

- 追加の対応先(note のほかのサイト)の記事の編集画面にも、下書きを入れられるようにした。今までは開発用のビルドだけで使えた。入れるときの権限の警告は増えない(`activeTab`・`scripting` と、そのサイトだけを後から許可する `optional_host_permissions`)。そのサイトのページでポップアップを開き、「使えるようにする」で許可した人だけが使える。下の「変えていないもの」にある追加の対応先の変更は、この版から使える
- 有料記事で本文に「ここから有料」の印があるとき、公開設定(ハッシュタグ・マガジン・有料・価格)を入れたら、「有料エリア設定」を押さずに公開設定の画面でいったん止まるようにした。確かめてから、バナーの「有料ラインを引く」を押すと、ラインを引いて止まる。今までは確かめる間もなくラインの画面に移り、ハッシュタグなどを見られなかった
- ポップアップのいちばん下の版をマウスで押したとき、版のまわりに青い枠(フォーカスの枠)が残らないようにした。Tab キーで移ったときは、今までどおり枠が出る(#209)

## 変えていないもの

- 追加の対応先の編集画面に入れるときは、note にだけある設定(目次・URL の埋め込み・マガジン・価格・最後のクレジット)を押せなくし、「(このページでは使えません)」と添える。入らない書き方の知らせにも出さない(開発用のビルドだけ)
- 追加の対応先の入口は、ストアの版では今までどおり出さない(開発用のビルド `EXTRA_SITE=1 npm run build` でだけ有効にして、そのエディタの診断を取れるようにした。#118)
- 追加の対応先の「使えるようにする」の案内は、開発用のビルドで、そのサイトのどのページ(エディタでなくてもよい)でも出るようにした。エディタ以外のページでは、使えるようにしてから新規記事エディタを開くよう案内する
- 追加の対応先の下書きの入力も、開発用のビルドでだけ動く。その編集画面のタブでポップアップを開くと、ボタンが「今開いているページに下書きを入れる」になり、今のタブにタイトル・本文・画像・タグを入れて止まる(「確認画面へ」「下書き保存」は押さない。#120)
- 追加の対応先の編集画面に出す知らせを、note の編集画面のバナーと同じ作りにした(開発用のビルドだけ)。入れているあいだは回る印・操作を控えるお願い・いま入れているもの(「本文の画像を入れています…(1/3 枚目: a.png)」など)を出し、入れ終えたら結果を出して、✓・⚠・✗ の行を色分けした「詳細」で開ける。「たたむ」で小さくでき、「閉じる」で消せる
- 追加の対応先の編集画面に入れるとき、front matter の `summary:` を「要約」の欄に入れるようにした(開発用のビルドだけ)。欄の上限より長いときは入れずに知らせる。`category:` は、選ぶ画面の作りを確かめるまで入れず、「画面で選んでください」と知らせる
- 追加の対応先のタグが入ったかの確かめ方を直した(開発用のビルドだけ)。公認タグの候補の並びや、打っている途中に出る文字を、入ったタグと取り違えていた。Enter キーも、キーの番号(keyCode)を見るページで受け取れるようにした
- 追加の対応先の診断レポートに、タグの欄・カテゴリの欄の中と、開いているダイアログ(カテゴリを選ぶ画面など)の中を出すようにした(開発用のビルドだけ)
- 追加の対応先のタグを入れ終えたあと、少し待って数え直し、いったん入ったのに画面から消えたタグを知らせるようにした(開発用のビルドだけ)
- 追加の対応先の診断レポートで、タグの欄の中に、ページ上部の隠れた検索欄を出していたのを直した。ダイアログの形でない選ぶ画面(カテゴリなど)の中も出す(開発用のビルドだけ)
- 追加の対応先の編集画面に入れるとき、front matter の `外部公開:`(全文公開 / 冒頭のみ公開)と `読了目安時間:`(表示する / 表示しない)も合わせるようにした(開発用のビルドだけ)。書いていなければ触らない
- 追加の対応先の許可を外してから付け直したときに、「Duplicate script ID」のエラーで使えるようにならないことがあったのを直した(開発用のビルドだけ)。登録が見えるまで少し待ち、それでも見えなければ消してから登録し直す
- 追加の対応先の編集画面に入れるとき、ポップアップに note のアカウント(「ログイン中」「記事の指定」)を出さないようにした(開発用のビルドだけ)。入れる先が note ではないのに note のアカウントが出て、どのアカウントで入るのかを取り違えるため
- 追加の対応先の診断レポートに、アカウントの表示らしい所(マイページのメニューなど。隠れているものも)の作りを出すようにした(開発用のビルドだけ)。名前・ID の文字は長さだけ、画像は src が https かどうかだけで、中身は出さない
- 追加の対応先の記事(front matter の target が note 以外)を、編集画面以外のページからも入れられるようにした(開発用のビルドだけ)。許可があれば、ボタンが「(追加の対応先) の新規記事を開いて下書きを入れる」になり、note と同じく新しいタブで新規記事のエディタを開いて入れる。エディタが開かなかったとき(ログインしていないなど)は、そのタブに知らせを出す
- 追加の対応先のページの知らせで、見出し・印・「たたむ」「閉じる」を 1 行に収めた(開発用のビルドだけ)。知らせの横幅を最大 560px にし、文字を折り返さない(画面が狭いときは見出しを … で切る)
- 追加の対応先の新規記事を新しいタブで開いて入れるとき、ログインしていなくても止まらずに、ログインし終えて編集画面に移るまで待ってから入れるようにした(開発用のビルドだけ。最大 10 分)。待っているあいだ、追加の対応先のページなら「ログインすると、そのまま入れます」と知らせる
- 追加の対応先に入れるときは、ポップアップに「(ドメイン): [アイコン] 名前」と、そちらのログイン中のアカウントを出すようにした(開発用のビルドだけ)。開いている追加の対応先のタブに出ているものを読むだけで、問い合わせはしない。名前の場所はまだ分かっていないので、今はヘッダーのアイコンだけ出る
- 追加の対応先のタグの入れ方を変えた(開発用のビルドだけ)。公認タグは候補のボタンを押して入れ、ほかのタグは、手で打ったときと同じく input と Enter の keydown だけを送る(keypress・keyup・change まで送ると、入ったタグが消えていた)。入ったかは、足したタグのボタンの数で確かめる
- 追加の対応先のタグを、記事の設定のうち最後に、画面が落ち着くのを待ってから入れるようにした(開発用のビルドだけ)。いったん消えた・入らなかったタグは 1 回だけ入れ直し、それでも残らなければ、タグの欄ごと作り直されたか、タグのボタンだけ消えたかを知らせる
- 追加の対応先のアカウントの名前も、ポップアップに出すようにした(開発用のビルドだけ)。名前はマイページの左の欄から読む。開いているページに名前が無ければ(編集画面など)、そのタブからマイページ(通知設定)を 1 回だけ GET で読む
- 追加の対応先のカテゴリを選ぶようにした(開発用のビルドだけ)。front matter の category(「大きなカテゴリ > 小さなカテゴリ」か小さなカテゴリだけ)と名前がちょうど 1 つ合うときだけ、「カテゴリを選択」を開いて選ぶ。合わない・2 つ以上あるときは選ばずに画面を閉じて知らせる
- 追加の対応先に入れるときは、「本文の確認を飛ばして、公開設定まで進む」のチェックも押せなくし、「(このページでは使えません)」と添える(開発用のビルドだけ)。追加の対応先は記事の設定も 1 回で入れて止まるので、このチェックは使っていなかった
- 追加の対応先で入れ終えたときの案内を短くした(開発用のビルドだけ)。ページのバナーは「✅ 下書きを入れました。」「「下書き保存」か「確認画面へ」を押してください。」の 2 行。ポップアップも「「下書き保存」か「確認画面へ」を、ページで押してください。」にそろえた
- 追加の対応先への許可を外したら、ポップアップのそのサイトのアカウントの行も消すようにした(開発用のビルドだけ)。今までは、許可を外しても名前とアイコンが残っていた
- 追加の対応先のページの知らせ(工程ごとの結果・入らない書き方・エディタを待つあいだ)の文を短くした(開発用のビルドだけ。#185)。入れていない欄(要約・カテゴリなど)は「詳細」に移した
- 追加の対応先に入れるとき、ポップアップの「② 入れる内容を確かめる」に、使えないマガジン・価格の行と欄を出さないようにした。見出しは「入れる内容」にした。ログイン中のアカウントは、入れる先のサイトのものだけを出す(今までは両方を並べていた)。ボタンの下の案内も、入れる先に合わせた(「新規記事を新しいタブで開いて、下書きを入れます。」「今開いているページに下書きを入れます。」)(開発用のビルドだけ。#191)
- 追加の対応先のカテゴリを、入れ終える前にもう一度確かめるようにした(開発用のビルドだけ)。記事の設定が作り直されると、ボタンの文字は残ったまま送る値だけが空になり、「確認画面へ」で「カテゴリを選択してください。」と出ていた。空なら 1 回だけ選び直す。診断レポートには、隠れた欄の値が入っているか(長さだけ)を出す
- 追加の対応先のタグを入れ直して全部入ったときは、⚠ ではなく、入れ直していないときと同じく「✓ タグ: 10 個」と出すようにした(開発用のビルドだけ)。全部入ったのに「一部は入れられませんでした」と出ていた。消え方はコンソールに残す
- 追加の対応先のページ(記事の一覧など)でポップアップを開いたとき、md を入れる前は、そのサイトのログイン中のアカウントを出すようにした。今までは note のアカウントが出ていた(開発用のビルドだけ。#201)
- 追加の対応先に入れるとき、記事の設定(タグ・カテゴリなど)を画像より先に入れ、画像を上げたあとはページの自動保存の返事を待つようにした(開発用のビルドだけ。#207)。自動保存の返事でページが記事の設定を描き直し、そのあいだに入れたタグとカテゴリの値が消えていた。返事が来たかは、ページの終わった通信の URL だけで見る(拡張の権限は増やしていない)
