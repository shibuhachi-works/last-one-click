## 詳細な説明

```
Markdown の記事から、note の「下書き」をまるごと作る Chrome 拡張です。
本文を貼るだけではありません。タイトル・本文・見出し画像・本文の画像・目次・ハッシュタグ・マガジン、有料記事の価格まで入れて、「投稿する」の手前で止まります。
md ファイル(記事のフォルダや ZIP でも可)を選んで 1 回押すだけ。最後のワンクリックは、あなたの手で。公開ボタンは押しません。

■ コピー＆ペーストとの違い
・画像も入ります: 見出し画像のアップロードとトリミングの保存、本文の画像(gif も)を、書いた位置に入れます。画像の URL を 1 枚ずつ貼り直す必要はありません
・本文の外も入ります: タイトル、ハッシュタグ、マガジン、有料記事の価格と有料ライン、目次、URL の埋め込み(カード)
・ハッシュタグも記事と一緒に: AI に記事を書かせるときに、ハッシュタグも記事ファイルの先頭に書いてもらえば、そのまま入ります
・書き換えにも使えます: 公開済みの記事を、md の内容で書き換えられます(「更新する」は押しません)
・アカウントを確かめられます: ログイン中の note アカウントを表示し、記事に書いたアカウントと違えば止まります

note のほかに、もう 1 つのサイト(追加の対応先)の記事の編集画面にも下書きを入れられます。そのサイトで「使えるようにする」を押して許可したときだけ使えます。

■ 省ける手間
これまで手でやっていた、この作業がまとめてなくなります。
・タイトルを入れ直す
・本文を貼ってから、見出し・太字・箇条書きを整え直す
・見出し画像をアップロードして、トリミングを保存する
・本文の画像を、1 枚ずつ貼る
・ハッシュタグを 1 つずつ打つ
・マガジンに追加する
記事ごとに繰り返していた作業が、ファイルを選ぶ 1 回で済みます。

■ 使い方
拡張のウィンドウは、手順の順に並んでいます。
1. ファイルを入れる: md ファイルと見出し画像をドラッグ＆ドロップ(記事のフォルダや ZIP でも、ボタンから選んでも可)
2. 入れる内容を確かめる: 記事ファイルの先頭から読んだタイトル・ハッシュタグ・マガジンが出ます。直すこともできます
3. 下書きを作る: 「note の下書きを作成」を押すと、note のエディタが新しいタブで開き、タイトル・本文・画像が入ったところで止まります
4. 本文を確かめて、右下のバナーの「公開設定を入れる」を押すと、ハッシュタグとマガジンが入ったところで止まります
5. 内容を確かめて、自分で「投稿する」を押します

■ 自動で入るもの
・本文の見出し・太字・箇条書き・引用・コード・リンク
・![説明](image1.png) のようにファイル名で書いた画像を、本文のその位置に(md と一緒にドロップした画像、または GitHub の同じフォルダの画像。1 記事 20 枚まで)。![説明](image1.png "キャプション") と書くと、画像の下のキャプションにも入ります。動く画像(gif)も入ります(横幅 620px 以下)
・URL だけを書いた行は、note の埋め込み(カード)に
・記事の先頭に note の目次(見出しの無い記事には入れません。ウィンドウの「記事の設定」で外せます)
本文の確認を飛ばして公開設定まで一気に進む設定も、「記事の設定」にあります。

■ リンクとハッシュタグ(チェックを外せば入りません)
記事の最後に「この記事は、Last One Click で下書きしました。」のリンクを入れ、ハッシュタグに #LastOneClick を足します。ウィンドウの「note の下書きを作成」のすぐ下のチェックで、入れるかどうかを選べます(最初はチェックあり)。

Last One Click を使って書かれた記事の中から、note のマガジン「Last One Click で書かれた記事」で、内容を見て紹介することがあります。リンクやハッシュタグを入れているかどうかは、紹介の条件にしません。

■ 公開済みの記事を書き換える
すでにある記事の編集画面でウィンドウを開くと、「この記事を書き換える」で、その記事のタイトル・本文・画像を md の内容に置き換えられます。
拡張は「更新する」「下書き保存」を押しません。確認して問題がなければ、自分で保存してください。保存せずに閉じれば、記事は変わりません。

■ 有料記事
有料記事にしたいときだけ、記事ファイルの先頭に price: 300 のように書くと、公開設定で記事タイプの「有料」を選び、価格を入れます。
本文に <!-- ここから有料 --> だけの行を書いておくと、公開設定の画面でいったん止まります。ハッシュタグ・マガジン・価格を確かめてから、画面右下のバナーの「有料ラインを引く」を押すと、その位置にラインを引いて止まります。
「有料で公開する」は押しません。セールの設定には触れません。

■ 公開ボタンは押しません
この拡張は、設計上、投稿・公開ボタンを一切押しません。
下書きのまま止まるので、公開前に必ず自分の目で確かめられます。
最後の 1 クリックはあなたが行います。

■ 安心して使えるように
・note のパスワードや Cookie には触れません
　ログイン済みの note のタブの中で動くだけです
・ログイン中のアカウントの名前とアイコンを、ウィンドウとバナーに出します
　違うアカウントで投稿しないためです。note のタブの中から note に 1 回問い合わせて読みます
　ウィンドウを開いたときに note のタブが無ければ、拡張から note に 1 回問い合わせます
　読んだ名前とアイコンは画面に出すだけで、保存も、note 以外への送信もしません
・サーバーを持ちません
　記事はあなたの Chrome の中に一時的に置かれ、note(と、許可した追加の対応先)以外には送られません
・追加の対応先は、そのサイトで「使えるようにする」を押して許可したときだけ動きます
　許可は、ウィンドウの「記事の設定」のスイッチでいつでも外せます
・GitHub のトークンは、上級者向けの設定で任意で入れられます
　入れた場合は、GitHub(raw.githubusercontent.com)から記事やセレクタ定義を読むときと、PR の URL から記事を探すとき(api.github.com)に付けて送ります
　GitHub 以外には送りません

■ 記事ファイル(md)の書き方
ファイルの先頭に、次のように書いておくと、タイトル・ハッシュタグ・マガジンが自動で入ります。どれも省略できます。
---
title: 記事のタイトル
hashtags: [AI活用, 個人開発]
magazine: マガジン名
---
## 大見出し
本文です。空行で段落が分かれます。
![画像の説明](image1.png "キャプション")
・hashtags は [A, B] でも、カンマ区切りでも書けます。「#」は付けても付けなくても構いません
・magazine は、note のマガジン名と完全に同じ名前にしてください
・見出し画像は、拡張のウィンドウに別のファイルとして入れます。記事のフォルダや ZIP をドロップするときは、先頭に thumbnail: ./thumbnail.png と書いておけば、その画像が見出し画像になります
・表は note 側が対応していないため、箇条書きに書き換えてください
・見出し画像は 1280×670px(note の推奨サイズ)にしておくと、そのまま全体が使われます

■ 注意
・note の運営元とは関係のない、非公式のツールです
・note の画面構成が変わると動かなくなることがあります
　その場合はサポート URL のお問い合わせから、拡張の「拡張機能の設定」の「診断」で取れるレポートを添えてご連絡ください
・ソースコードは GitHub で公開しています(MIT ライセンス)
　https://github.com/shibuhachi-works/last-one-click

▼ 使い方の記事(note)
https://note.com/shibuhachi/n/n9c41926f2a3a
```

## 単一の目的(Single purpose)

```
note.com のエディタ(と、ユーザーが許可した追加の対応先の記事の編集画面)に、ユーザーが選んだ Markdown ファイルの記事を下書きとして入力すること。公開・保存のボタンは押さない。
```

## 権限の理由(Permission justification)

| 権限 | 理由 |
|---|---|
| `storage` | 組み立てた記事(タイトル・本文 HTML・画像)を、ポップアップから note のタブへ渡すために一時的に保存する。任意の GitHub トークンと設定もここに保存する。外部には送らない |
| `clipboardWrite` | 「診断」ボタンで、note の画面の入力欄・ボタンの一覧(認証情報や本文を含まない)をクリップボードにコピーし、不具合の報告に使えるようにする |
| ホスト権限 `https://note.com/*`, `https://editor.note.com/*` | note のエディタのページで content script を動かし、タイトル・本文・画像・ハッシュタグ・マガジンを入力するため。また、ログイン中のアカウントの名前とアイコンを表示するため、ユーザーの note のタブの中から、ログイン中のユーザーの情報を返す note の問い合わせ(GET)に 1 回だけ問い合わせる。ポップアップを開いたときに note のタブが無ければ(またはタブから返事が無ければ)、拡張の service worker から同じ問い合わせを 1 回だけ行う(Cookie は読まない。`cookies` 権限は持たない。定期的には問い合わせない)。結果は画面に出すだけで、保存も、note.com 以外への送信もしない |
| `activeTab` | 追加の対応先のページのタブでツールバーのアイコンを押したときだけ、そのタブが記事の編集画面かどうかを、読むだけの関数を 1 回動かして確かめるため(案内の文とボタンを変えるため)。ほかのサイトのタブでは何も動かさない |
| `scripting` | ユーザーが「使えるようにする」で追加の対応先を許可したときだけ、そのサイトの content script を登録する(許可を外せば登録も外す)。上の確かめにも使う |
| 任意のホスト権限(`optional_host_permissions` の 1 ホスト。manifest にあるもの) | 追加の対応先の記事の編集画面に、ユーザーが選んだ記事を下書きとして入れるため。入れるときには求めず、ユーザーがポップアップの「使えるようにする」を押したときだけ求める。ログイン中のアカウントの名前とアイコンを出すため、ページに名前が無いときだけ、同じサイトのマイページを 1 回 GET で読む(Cookie は読まない)。読んだものは画面に出すだけで、保存も、そのサイト以外への送信もしない |
| ホスト権限 `https://raw.githubusercontent.com/*` | (1) 記事の Markdown・見出し画像・本文の画像を GitHub から読む(ユーザーが URL を渡したときだけ)、(2) note の画面構成の変更に追従するためのセレクタ定義(JSON。コードではない)を読む |

## リモートコード(Remote code)

```
使用していません。GitHub から読むのはセレクタ定義の JSON と、ユーザーが指定した Markdown/画像だけで、コードは実行しません。
```

## データの使用(Data usage)

- 収集するデータ: **なし**(個人を特定できる情報・健康・金融・認証情報・個人の通信・位置情報・閲覧履歴・ユーザーの操作・ウェブサイトのコンテンツ、いずれも収集・送信しない)
- 認定(3 つのチェック): すべて「はい」
  - 承認された用途以外でデータを販売・使用しない
  - 単一の目的と関係のない用途でデータを使用・転送しない
  - 信用力の判断や融資の目的でデータを使用・転送しない
