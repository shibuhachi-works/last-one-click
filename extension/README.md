# Last One Click(Chrome 拡張)

**The last one click is yours.**

Markdown のファイルを選ぶだけで、note の下書き(タイトル・本文・見出し画像・ハッシュタグ・マガジン)を自動で組み立てる拡張です。
**公開ボタンは押しません。** 最後は自分で確認して押してください。

Chrome ウェブストアと chrome://extensions では「Last One Click - note の下書きツール」の名前で出ます(ツールバーなど狭い所では「Last One Click」)。

## ストアから入れる

[Chrome ウェブストアで入手](https://chromewebstore.google.com/detail/last-one-click/jomapffkhcdpnodaffobmpfofnnaihnd)(Chrome と Edge などの Chromium 系ブラウザで使えます)。通常はこちらをお使いください。以下は、開発版を手元でビルドして入れる方法です。

**使い方の記事**:[AIが書いた記事から 3ステップでnoteの下書きを作る方法(note)](https://note.com/shibuhachi/n/n9c41926f2a3a)。md の型・AI への頼み方・GitHub から読み込む手順などを、詳しく書いています。

## 認証について

この拡張は note の **Cookie・パスワードに一切触れません**。
content script は「あなたが開いている note.com のタブ」の中で動くので、そのタブが既にログイン済みならそのまま使えます。
サーバーも持っていないので、認証情報がどこかに送られることもありません(`manifest.json` に `cookies` 権限がないことで確認できます)。

ログイン中のアカウントの名前とアイコンを出すため、note のタブの中から、ログイン中のユーザーの情報を返す note の問い合わせ(`selectors/note.json` の `account.currentUserUrl`)に 1 回だけ GET で問い合わせます。ポップアップを開いたときに note のタブが無ければ(またはタブから返事が無ければ)、拡張の service worker から note.com に同じ問い合わせを 1 回だけ行います。Cookie はブラウザが付けるだけで、拡張は読みません。読んだ名前・ID・アイコンの URL は画面に出すだけで、保存も、note.com 以外への送信もしません。問い合わせるのは、ポップアップを開いたとき・下書きを入れ終えたとき・公開設定を入れたあと・診断のときだけです。

## インストール(開発版)

```bash
cd extension
npm install
npm run build        # → dist/ ができる
```

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」→ `extension/dist/` を選ぶ

### 追加の対応先で使う(v0.2.0 から)

note のほかに、追加の対応先の記事の編集画面にも下書きを入れられます。入れるときの権限の警告は増えません。そのサイトのページ(記事の一覧など、エディタでなくてもよい)でツールバーのアイコンを押すと、ポップアップに「使えるようにする」の案内が出ます。押して許可すると(このホストだけ。`optional_host_permissions`)、そのサイトの記事の編集画面(新規でも下書きでもよい)のタブでポップアップを開いたとき、「note の下書きを作成」のボタンが「今開いているページに下書きを入れる」になります。押すと、新しいタブは開かず、今のタブにタイトル・本文・記事の設定(外部公開の範囲・カテゴリ・要約・読了目安時間・タグ)・見出し画像・本文の画像(png・jpg だけ)を入れて止まります。中身を確かめてから、そのページの「下書き保存」か「確認画面へ」を自分で押してください(拡張はどちらも押しません)。追加の対応先のエディタで入らない書き方(目次・埋め込みなど)は、ポップアップとページの知らせに出ます。セレクタは `selectors/extra-site.json`(無くても、コードの既定値で動きます)。許可は、ポップアップの「記事の設定」のスイッチでいつでも外せます。

## 使い方

1. note.com に普通にログインしておく
2. ツールバーの拡張アイコンをクリックする。ポップアップは手順の順に並んでいる
3. **① ファイルを入れる**: AI が生成した Markdown のファイル(`.md`)と見出し画像を「md ファイルを選ぶ」「画像を選ぶ」で選ぶ(記事のフォルダ・ZIP でもよい)。ドロップするときは、先に右上の「ウィンドウで開く」で別のウィンドウにしておく(ツールバーのポップアップは、Finder などに切り替えると閉じるため。下の「ドラッグ＆ドロップで渡す」)
4. **② 入れる内容を確かめる**: front matter から読んだタイトル・ハッシュタグ・マガジン・価格が、短い一覧で出る。直すときは「直す」を開く(送られるのは欄の値)。md の全文は「読み込んだ md を見る」で見られる
5. **③ 下書きを作る**: ボタンのすぐ上の「note.com: [アイコン] 名前」で、投稿したいアカウントか確かめて(note のタブを開いていなくても出る)、「note の下書きを作成」を押す
6. note のエディタが新しいタブで開き、タイトル・本文・見出し画像が入ったところで止まり、右下に緑のバナーが出る。バナーには「作成に使った note のアカウント: [アイコン] 名前」も出る
7. 本文を確認する(下書き保存・プレビューもここで)。よければバナーの「公開設定を入れる」を押すと、拡張が「公開に進む」を押し、ハッシュタグ・マガジンを入れて止まる
8. 内容を確認して、**自分で「投稿する」を押す**

「記事の最後に『Last One Click で下書きしました』のリンクと、ハッシュタグ #LastOneClick を入れる」は、「note の下書きを作成」のすぐ下にあり、既定でチェックが入っています。入れたくないときは外してください(次回も同じ)。
その下の「記事の設定」(たたんである。見出しの横に、いまオンになっているものが出る)には、次の 2 つがあります。

- 「本文の確認を飛ばして、公開設定まで進む」: 入れると、6〜7 で止まらずに公開設定まで一気に進みます(次回も同じ)
- 「記事の先頭に目次を入れる」(既定でチェックあり): 本文を貼る前に note のエディタの「+」→「目次」を押し、本文の先頭に note の目次を入れます(チェックを外すと入れません。チェックは次回も同じ)。目次は本文の見出し(`##`・`###`)から note が作ります。見出しが無い記事には入れず、バナーで知らせます。目次を入れられなかったときは止まらずに先へ進み、バナーで知らせます。そのときは note の画面で、本文の先頭の行で「+」→「目次」を押してください。

(次の 2 つは、切るチェックが無く、いつも行う)URL だけが書かれた行は、本文を貼ったあと、その行の末尾で Enter を押し、いつも note の埋め込み(カード)にします。文の中のリンクはそのままです。1 記事 20 件までで、それを超えた分と、埋め込みにできなかった URL は行のまま残し、バナーで知らせます。そのときは note の画面で、その URL の行の末尾で Enter を押してください。
md の `![説明](image1.png)` のようにファイル名で書いた画像を、いつも本文のその位置に入れます。GitHub から読み込んだときは記事と同じフォルダから取り、手元の md のときは md と一緒にドロップした画像から、ファイル名で探します(md に書いていない画像は見出し画像になります)。1 記事 20 枚・本文と見出し画像と合わせて約 6MB まで。入れられなかった画像は、本文に目印(［画像1・ab12: image1.png］のような文字)を残してバナーで知らせるので、その位置に note の画面で入れてください。`![説明](image1.png "キャプション")` のように `"…"`(title)を書くと、画像の下のキャプションにも入れます(`説明` の部分は入れません)。URL(https://…)で書いた画像は、これまでどおりです。

公開設定を「キャンセル」で閉じると、入れたハッシュタグとマガジン(有料記事では、有料・価格と有料エリアのラインも)は note 側で消えます。下書きを保存して開き直したときも、有料・価格と有料エリアのラインは残りません(note の動き)。本文を直したあとは、バナーの「もう一度入れる」を押すと入れ直します(ページを再読み込みした場合は、ポップアップからもう一度実行してください)。

### Markdown の形

書き換えて使える見本は [templates/note/](../templates/note/) にあります。

```markdown
---
title: 記事タイトル
hashtags: [AI, 個人開発]
magazine: マガジン名       # 省略可
---

## 本文はここから
```

- `title` が無ければ本文の最初の `# 見出し` を使う
- `hashtags` は `[a, b]` / `a, b` / `#a #b` / YAML のリスト、どれでも可
- `price: 300` と書くと有料の記事にする。公開設定を入れるときに「有料」を選び、価格(円)を入れる。1 以上の整数だけで、ほかの値はエラーになる。本文に下の印が無ければ、「有料」を選ぶと出る「有料エリア設定」は押さないので、どこから有料にするかは note の画面で決める。書かなければ記事タイプには触らない(無料のまま)
- `price` と一緒に、本文に `<!-- ここから有料 -->` だけの行を書くと、公開設定の画面でいったん止まる(v0.2.0 から)。ハッシュタグ・マガジン・価格を確かめてバナーの「有料ラインを引く」を押すと、「有料エリア設定」を押し、その行の直前の段落のすぐ下にある「ラインをこの場所に変更」を押して止まる(「投稿する」は押さない)。何番目のボタンかではなく、直前の段落の文字で場所を探す。同じ文字の段落が無い・2 つ以上あるときは押さずに「手でラインを引いてください」と出す。印は 1 つだけで、本文の最初には置けず、`price` が無いとエラーになる。印の行は本文に入らない(コードのかたまりの中の印は文字のまま)
- `note_account: example` のように、記事を作る note のアカウントの ID(`note.com/<ID>` の部分)を書くと、ポップアップに「記事の設定: example」を出し、編集画面で入力を始める前にログイン中のアカウントと比べる。違えば、タイトルも本文も入れずにバナーで「ログイン中のアカウント(◯◯)が、記事の設定(◯◯)と違います」と知らせて止まる(ポップアップでも、ログイン中のアカウントが読めていて違えば注意を出す。ボタンは押せる)。大文字と小文字・先頭の `@` は区別しない。ログイン中のアカウントが読めないときは止めずに進み、バナーに「アカウントを確認できませんでした」と出す。書かなければ比べない(今までどおり)。比べるだけで、保存も送信もしない
- `note_url: https://note.com/<アカウントの ID>/n/<記事の ID>` のように、書き換える記事の URL を書くと、開いている記事の編集画面がその記事でなければ「この記事を書き換える」を押せなくする(下の「開いている記事を書き換える」)。新しい下書きを作るときは使わない
- md ファイルを読み込むと「note に入れる内容」(タイトル・ハッシュタグ・マガジン・価格)が md ファイルから読んだ値で出る。直したければ「直す」を開いて直す(送られるのは欄の値)。md ファイルにタイトルが無いときは赤枠になるので入力する
- 本文で使える記法の一覧はリポジトリ直下の [README.md](../README.md)「本文で使える記法」を参照。表は note 非対応なので、記事を書く側で「表は箇条書きに展開する」と決めておく

### ドラッグ＆ドロップで渡す

md ファイルと見出し画像は、ポップアップにドロップしても渡せます(2 つ同時でも可)。記事のフォルダや、md と画像をまとめた ZIP をそのままドロップしてもかまいません(md が 2 つ以上あるときは `article.md` か `index.md` を記事として読みます。ZIP の中の md と画像は合わせて 60MB・1000 個まで)。フォルダ・ZIP のときは、本文に書いた画像を本文の画像に、front matter の `thumbnail` に当たる画像を見出し画像にします。ツールバーのポップアップは Finder などに切り替えた瞬間に閉じるので、ドロップするときは右上の「ウィンドウで開く」で独立したウィンドウにしてから、そこへドロップしてください。

### 見出し画像

front matter の `thumbnail: ./xxx.png` のような相対パスは、GitHub から読む場合と、記事のフォルダ・ZIP をドロップした場合に使います。md だけを渡したときはブラウザが辿れないので、見出し画像はドロップ領域に落とすか「画像を選ぶ」で選んでください。

見出し画像は **1280×670px(note の推奨サイズ)** にしておくと、そのまま全体が使われます。それ以外の比率でも note のトリミング画面の初期状態(ズームなし)で保存するので壊れませんが、切り抜き方を変えたいときは note の編集画面で見出し画像を直してください。アップロード後は、トリミング画面に画像が表示されてから「保存」を押し、記事側に画像が表示されるまで待ちます(確認できなければそこで止まり、画面で確かめてからバナーの「公開設定を入れる」で先へ進めます)。

### 開いている記事を書き換える

すでにある記事(公開済み・下書き)の編集画面(`editor.note.com/notes/<記事の ID>/edit`)を開いた状態でポップアップを開くと、「今開いている記事:『(タイトル)』」が出て、ボタンが「この記事を書き換える」になります。新しい下書きを作りたいときは、その下の「新しい下書きとして作る」を押します。

- 書き換えるもの: タイトル・本文(今の本文を消してから入れる)・目次・本文の画像・埋め込み・見出し画像。新しいタブは開かず、今のタブに入れて止まる
- 書き換えないもの: ハッシュタグ・マガジン・価格・有料ライン。これらは公開設定の画面で入れるもので、公開設定の画面に移ると記事が保存される可能性があるため、拡張は「公開に進む」を押さない。md に書いてあるものは、バナーに並べて知らせるので、変えたいときは公開設定の画面で自分で入れる
- 「本文の確認を飛ばして、公開設定まで進む」は、書き換えでは使えない(同じ理由)
- 拡張は「公開に進む」「更新する」「下書き保存」を押さない。note は自動では保存しないので、元に戻したいときは、保存せずに閉じれば記事は変わらない。拡張は前の本文を保存しない
- 見出し画像は、ボタンが見つかったときだけ差し替える(見つからなければバナーで知らせるので、画面で差し替える)
- md に `note_url` を書いておくと、別の記事を開いていたときに書き換えない
- ポップアップを「ウィンドウで開く」で開き直しても、同じ記事を書き換える

### GitHub から読む場合(上級者向け。普段は隠れている)

「拡張機能の設定」を開いて「上級者向けの設定を表示する」にチェックを入れると、「GitHub から読み込む」と、selectors の URL・GitHub トークンの設定が出て、読み込んだ内容の欄が編集(貼り付け)できるようになります(チェックを外すと隠れる。状態は覚える)。
「GitHub から読み込む」に記事ディレクトリの URL(`.../tree/main/posts/xxx`)を貼ると md ファイルを取得し、② に出します。
PR の URL(`https://github.com/<owner>/<repo>/pull/123`)も貼れます。その PR で足したり直したりした `article.md` を、PR の最新のコミットの中身で読みます。記事が 2 本以上ある PR では、読む記事を選ぶ欄が出ます。相対パスの画像・見出し画像は、その `article.md` と同じフォルダから取ります。PR に画像を足したり差し替えたりしたら、もう一度「読み込む」を押すと最新のコミットで取り直します。拡張の権限は増えません(GitHub の API はどこからでも読めるように開かれています)。
front matter の `thumbnail: ./thumbnail.png` も同じディレクトリから自動で取ります。private リポジトリは GitHub トークンを入れてください(`Contents: Read` だけで十分。PR の URL で読むときは `Pull requests: Read` も)。

## note の画面が変わって動かなくなったら

セレクタは拡張に埋め込まず、起動時に GitHub 上の `selectors/note.json` を読みます(1時間キャッシュ、失敗時は同梱コピー)。

```
note の DOM が変わる
  → リポジトリの selectors/note.json を直して push
  → 全ユーザーの拡張が次回起動時に新しいセレクタを使う(ストア再申請なし)
```

既定ではこのリポジトリの `main` の `selectors/note.json` を読みます。フォークした場合は `src/lib/selectors.ts` の `DEFAULT_SELECTORS_URL` を変えるか、ポップアップの「拡張機能の設定」で URL を指定してください。
リポジトリが private の間は、「拡張機能の設定」(上級者向けを表示した状態)に GitHub トークン(`Contents: Read`)を入れておくと取得できます。入れていなければ同梱コピーにフォールバックします。

セレクタの差し替えで済まない変更(工程が増えた、入力方式が変わった等)は `src/content.ts`(工程の中身は `src/lib/content/`)の修正と再ビルド・再配布が必要です。
壊れた箇所の調査は、同じ `selectors/note.json` を読む Playwright 版(`../tools/draft.ts`)のほうが楽です。

## ファイル構成

```
manifest.json          # MV3。権限は storage・clipboardWrite・activeTab・scripting と note.com / raw.githubusercontent.com。追加の対応先は optional_host_permissions(許可されたときだけ)
build.mjs              # esbuild でバンドル → dist/
package.mjs            # dist/ を ZIP にする(ストアに上げる用)
icons/                 # icon.svg(全サイズ共通の元)と PNG(render.mjs で生成)
store/                 # ストアの掲載文(listing.md)・スクリーンショット・生成スクリプト
src/
  popup.html/css/ts    # 入力 UI。記事を組み立てて chrome.storage に置き、note を開く(開いている記事の編集画面なら、そのタブを書き換える)
  content.ts           # note.com のタブで動く。pending の記事をエディタに入力して止まる(工程の順番と、ポップアップからの知らせの受け口)
  background.ts        # service worker。content script に自分のタブ ID を教える(ポップアップが開いたタブでだけ動かすため)。追加の対応先の登録を許可に合わせる
  extra-site.ts        # 追加の対応先のページで動く content script(許可されたときだけ登録する。診断のレポートを返し、ポップアップから受けた記事をこのタブに入れる)
  lib/
    article.ts         # md → ArticlePayload(GitHub 取得・サムネイルの base64 化。front matter などは ../shared/article.ts)
    selectors.ts       # selectors/note.json の読み込み(remote → cache → bundled)
    extra-site.ts      # 追加の対応先の許可・登録・確かめを chrome の API につなぐ(中身は ../shared/extra-site.ts)
    diagnose-extra-site.ts # 追加の対応先のエディタの診断(読むだけ。中身・名前・ID は出さない)
    extra-site-fill.ts # 追加の対応先の編集画面に、記事を下書きとして入れる(「確認画面へ」「下書き保存」は押さない)
    types.ts           # 型と storage キー
    content/           # content.ts の中身を役割ごとに分けたもの
      dom.ts           #   DOM を探す・待つ・入れるための小さな道具
      banner.ts        #   右下のバナーと、工程の結果の記録(step・StopError)
      editor-steps.ts  #   編集画面の中の工程(タイトル・目次・本文・埋め込み・本文の画像・本文を消す)
      eyecatch.ts      #   見出し画像の工程
      publish-settings.ts #  公開設定の画面の工程(ハッシュタグ・マガジン・有料・価格・有料ライン。「投稿する」は押さない)
    popup/             # popup.ts の中身を役割ごとに分けたもの(popup.ts には、ボタンなどへの登録と開いたときの処理だけを残す)
      state.ts         #   開いているあいだだけ持つ状態(読み込んだ取得元・本文の画像・入れる先など)
      elements.ts      #   画面の要素と、決まった値
      dom.ts           #   要素を ID で取る・知らせを出す・アカウントの 1 行
      destination.ts   #   入れる先(新しいタブ・開いている記事の書き換え・追加の対応先)と、ボタンの文字・押せる設定
      account.ts       #   ログイン中のアカウントと、記事の設定(note_account)の表示
      fields.ts        #   「② 入れる内容を確かめる」の欄と、受け取ったファイルの表示
      sources.ts       #   記事を受け取る(GitHub・md ファイル・ドロップ・フォルダや ZIP)
      submit.ts        #   下書きを作るボタンの中身(組み立てて送る)
      settings.ts      #   記事の設定・上級者向けの表示・診断のコピーの表示
      zip.ts           #   ドロップされた ZIP を読む
      extra-site-message.ts # 追加の対応先に渡す記事と、入らない書き方の知らせ
../shared/                  # Playwright 版と共通の純粋ロジック(front matter、URL、安全装置 など)
../selectors/note.json      # note のセレクタ(Playwright 版と共有)
```

## 動かなくなったとき

`selectors/note.json` の値は 2026-10-29 に実機で全工程 ✓ を確認済みです。note の画面が変わって ✗ になったら、

1. 拡張を実行し、右下のバナーで ✗ になった工程を確認する
2. **その note のタブを開いたまま**、ポップアップの「拡張機能の設定」→「診断(動かないとき)」→「DOM 情報を取得」を押す
3. コピーされたレポート(入力欄・ボタン等の一覧と、今の selectors/note.json が何件マッチしたか)を、修正する人に貼って渡す
4. `selectors/note.json` の該当キーを直す → `npm run build` → `chrome://extensions` で再読み込み(または GitHub に push して拡張を再起動)

公開設定画面の要素は、公開設定を開いた状態でもう一度「DOM 情報を取得」すると取れます。
レポートには認証情報や記事本文は含まれません(URL のクエリも除いています)。

## ストアに出すとき

手順は [../docs/store-submission.md](../docs/store-submission.md)、掲載文と審査の回答は [store/listing.md](store/listing.md)。

```bash
npm run package       # → release/last-one-click-<version>.zip(ストアに上げるファイル)
npm run icons         # icons/icon.svg → icon16/32/48/128.png
npm run screenshots   # store/screenshot-1.png(1280x800)と store/promo-small.png(440x280)
```

`icons` と `screenshots` はリポジトリ直下の Playwright(Chromium)で描画するので、先に直下で `npm ci && npx playwright install chromium` を済ませておく(拡張の依存には入れていない)。

- 説明文に「認証情報を扱わない」「公開ボタンは押さない」「非公式ツール」を明記する(listing.md に入っている)
- `host_permissions` は上記3ドメインから増やさない(増やすほど審査が厳しくなる)
- プライバシーポリシーは [../docs/PRIVACY.md](../docs/PRIVACY.md)(ストアには公開 URL が必要)
